## 3. 进化回路实测

- `evolve mark` 标记 git config 为误报（并给出 `product=Nginx`、`body=repositoryformatversion`）；
- 重新评分后该命中 **D0 / “人工标记误报，不提交”**，不再生成证据包；
- `evolve propose` 产出 **2 条候选**（1 检测模板 + 1 指纹规则），**2/2 passed**：
  - 模板：正样本命中 `/download?...`，负样本 0 命中；
  - 指纹：正样本仍识别 Nginx，负样本不识别；
- `evolve approve` → **版本 v1**（快照 + 指标）；
- `evolve rollback --version 1` → 规则库恢复，**版本 v2 记录回滚**，`ah-fp-*` 规则消失。

结论：**进化回路确实能自动产出候选并完成正负样本回归**；但候选质量依赖证据质量，
必须人工审核（本轮 REVIEW.md 与 `<id>.validation.json` 均保留）。

## 7. 未完成与风险

1. **历史 URL 在线源未内置**：gau/waybackurls 需导出后离线导入；在线 CDX 查询会访问外部服务，开发期不允许。
2. **JS 动态端点**：只做正则提取，未执行 JS；打包/拼接的接口可能漏。
3. **扫描请求数是估算**：nuclei 内部请求未逐条审计；成本指标会偏高（按 15/URL）。
4. **并行批量的写锁**：并行度 >1 时多进程写同一 SQLite 可能出现锁等待，默认串行规避。
5. **候选质量**：稳定片段/负条件都是启发式，必须人工审核；负样本只有一个干净靶场，覆盖有限。
6. **未接真实资产**：本轮所有验证均在回环环境，真实网络下的 WAF/CDN/超时分布需首跑 light 观察。
