# 目标体检（triage）

## 1. 模式定义与硬约束

`triage` 只做侦察与研判，不进入漏洞验证：

```
seed/import 种子 → 存活探测 → 指纹识别 → 暴露面梳理 → 离线风险研判 → triage.md / triage.json
```

硬约束：

- **零扫描请求**：不 import / 不调用 nuclei、`core.scanner`、`adapters.run_scan` 或任何模板扫描；
  审计中只出现 `triage-probe` / `triage-exposure` 两类请求，测试会断言没有 `scan`/`finding` 事件。
- 独立请求预算：默认 **60** 次/目标（配置 `triage.max_requests`，CLI `--max-requests`，硬顶 200）；
  与全局令牌桶、日配额、熔断、审计共用。
- 种子只允许 `seed`（目标声明）与 `import`（本地清单），不访问外部数据源、不做子域爆破。
- 复用授权校验：目标必须有 authorization、范围非空；档案 `automation_allowed=no` 直接拒绝。
- 报告中的风险方向、重复概率、成本、结论全部是**推断**，不是已发现漏洞；所有推测均标注“推断”。

## 2. 七块内容口径

| 块 | 数据来源 | 口径 |
|---|---|---|
| 1. 基础面 | 存活探测响应 | 存活主机数、端口、状态码分布、响应耗时中位数、请求预算用量 |
| 2. 技术栈 | FingerprintEngine + 标题/Server/正文版本提取 | 产品、版本、版本来源、置信度；带版本号的排前面 |
| 3. 暴露面 | 固定 GET 路径探测 | 管理后台、登录、API 前缀、上传、调试/文档、备份迹象；仅记录状态/标题，不做利用 |
| 4. 风险方向 | 本地 `data/triage_risks.yaml` + 版本线 | 产品/版本 → 可参考的 CVE/Nday 方向；全部为推断 |
| 5. 重复风险 | 本地 hot 产品 + `known_disclosures` | “高重复概率”标记与理由；全部为推断 |
| 6. 成本预估 | standard profile 参数 + 存活主机数 | 正式扫描预估请求数/耗时/建议档位；未实际扫描 |
| 7. 结论 | 上述信号评分 | 建议深挖 / 可试 / 不建议，附一句理由 |

## 3. 判定三档

评分信号（示例）：

- 带版本号的技术栈：每个 +2（上限 +6）
- 离线风险方向：每条 +2（上限 +6）
- 可访问/受保护的暴露面类别：每类 +2（上限 +6）
- 备份文件可访问：+2
- 存活主机：基础 +1；≥3 台再 +1
- WAF/CDN：-4
- 高重复概率产品：-3
- 未识别技术栈：-2
- 暴露面统一 403：-2
- 无指纹且无可用暴露面：-3
- 预算用尽：-1（基于部分数据）

阈值：

- **建议深挖**：评分 ≥ 8
- **可试**：4 ≤ 评分 < 8
- **不建议**：评分 < 4；无存活响应直接 -10

结论始终标注“推断”，并列出触发信号；不写成“存在漏洞”。

## 4. 本地三档靶场验证

靶场 `outputs/triage-demo/lab_server.py`：

| 模式 | 特征 | 实测请求 | 检出/判定 |
|---|---|---|---|
| cms | WordPress 5.8.2；管理/登录/API/上传/文档/备份可访问 | 13/60 | **建议深挖**（评分 16） |
| waf | Cloudflare 头；暴露面统一 403；无指纹 | 13/60 | **不建议**（评分 -10） |
| static | 纯静态 HTML；无指纹、无暴露面 | 13/60 | **不建议**（评分 -4） |

CMS 报告包含：Nginx 1.18.0（Server 来源）、WordPress 5.8.2（标题来源）、6 类暴露面、
3 条推断风险方向、1 条高重复提示、正式扫描成本估算；实际数据来自探测响应，不是模板生成。

零扫描验证：

- 审计事件仅 `triage-probe` / `triage-exposure`；
- 无 `finding` 事件、无 `scan` 阶段、无 nuclei 调用；
- 测试读取 `triage.py` 源码，断言不含 `run_scan` / `core.scanner`；
- 请求预算 `used <= 60`。

其他测试：空目标（无种子 → 不建议，0 请求）、全部 403（WAF 样本）、超时（无存活 → 不建议）、
指纹识别不出来（static 样本）、预算用尽（max_requests=5）。

## 5. 配置与使用

### 5.1 config/recon.yaml

```yaml
triage:
  max_requests: 60
  max_hosts: 50
  max_exposure_paths: 12
  sources: ["seed", "import"]
  max_body_chars: 4096
```

### 5.2 CLI

```bash
python main.py triage -t targets/authorized/xxx.yaml
python main.py triage -t targets/authorized/xxx.yaml --max-requests 40
python main.py triage -t targets/authorized/xxx.yaml --profile light --fresh
```

### 5.3 面板

「目标体检」页填写厂商、授权依据、范围、禁止项、请求上限与授权确认，提交后进入同一套串行队列。
结果区按七块展示：基础面、技术栈、暴露面、风险方向、重复风险、成本、结论；
支持导出 `triage.md` / `triage.json`。

### 5.4 产物

与既有状态目录一致：`<state>/<target>/triage.md`、`triage.json`，并写一份最小 `summary.json`
（`kind=triage`）供面板运行列表发现。没有 `findings.jsonl`、没有证据包、没有扫描产物。

## 6. 与正式扫描的差异

| 维度 | 目标体检 triage | 正式扫描 recon/batch |
|---|---|---|
| 目的 | 判断值不值得深挖 | 验证漏洞并产出证据 |
| 请求 | 默认 ≤60，只做存活/指纹/有限暴露面 | 采集+发现+扫描，请求更多 |
| nuclei | 完全不调用 | 按档位/模板扫描 |
| 输出 | 研判报告（推断） | findings.jsonl + 证据包 + 报告 |
| 结论 | 建议深挖/可试/不建议 | 命中/未命中，需人工复核 |
| 风险 | 低（只读探测，不利用） | 中（模板扫描仍有请求与误报风险） |

## 7. 已知限制

- **不验证漏洞**：风险方向只是离线映射，不能证明目标存在 CVE；结论可能高估或低估。
- **不扫目录/不爆破**：暴露面只探测固定少量路径；未链接的管理入口、备份文件可能抓不到。
- **不解析 JS 路由/API**：只做固定路径探测，单页应用的深层接口可能遗漏。
- **指纹依赖特征**：页面特征不足、WAF 改写响应、登录后才展示的产品会识别不出来。
- **版本来源有限**：版本从标题/Server/正文前段推断，可能被主题/插件/反代伪造；报告中标注来源。
- **WAF/统一 403**：只能看到拒绝，无法判断真实暴露面；结论通常降为不建议/可试。
- **成本是估算**：按 standard profile 和资产数估算，未考虑实际网络、模板数量和目标响应速度。
- **只允许 seed/import 种子**：不做子域爆破/外部测绘 API；资产清单不足时体检覆盖面有限。
- **零扫描是代码路径约束**：测试基于审计与源码断言；若未来新增扫描调用，需要同步更新这条红线。
